## 025 의료정보 안전 규칙(v02) — '기존 값을 무기한 공개하지 않는다'
| 상황 | 공개 화면 | 기한 |
|---|---|---|
| 병원 진료시간·과목·종별·전화 변경 감지 | 그 칸을 비우고 **'확인 중'** 표시(앱: "진료시간 확인 중 — 전화로 확인"), 지금 진료 중 필터에서 제외 | 7일(reconfirm_days) 안에 승인 없으면 그 의원 **비공개** |
| 원천 목록에서 사라짐(폐업·종료 의심) | **즉시 비공개** | 승인(폐업 확정)으로 종결, 다시 나타나면 자동 복귀 |
| 혜택 조건(대상·내용·연락처·링크 등) 변경 | 그 사업 **비공개**(조건을 비운 채 보여 주지 않음) | 14일 안에 승인 없으면 계속 비공개 |
| 학교·학원 식별 정보 변경 | 그 기록 비공개 | 14일 |
| 원천이 원래 값으로 복귀 | 자동 원복·표시 해제 | — |
| 승인 result 승인 / 기각 | 새 값 공개 / 원래 값 그대로 공개 | 결과는 `ops/changes/<구>.json` `verify_result` 로 보존 |
| 바뀐 기록이 20~30% 넘음 | 파일째 보류(직전본 유지) | 원천 형식 변화 의심 |

기존 공개 정보의 재검사: 매 수집마다 이미 '확인 중'인 기록의 기한·원복·재출현을 다시 판정하고, 사라졌던 기록이 돌아오면 복귀시킨다. 비공개됐던 기록이 다시 수집돼도 '추가'로 몰래 공개되지 않는다(보류 기록과 대조).

## 재검증 승인 절차(사람)
1. 관리자 상태판 '검증 필요' 또는 `review/<구>/_reverify.json` 에서 항목 확인(before/after·source_url·first_seen).
2. 원문(심평원·E-Gen·복지로·나이스)과 대조.
3. `approvals/reverify.json` 의 `items` 에 `{city, file, key, approved_at, by, note}` 추가(여러 건이면 `key:"*"` + `all_pending_before`).
4. 다음 수집(daily 05:30 / hospitals 월요일)에서 새 값이 공개되고 `ops/changes/<구>.json` 에 '적용(승인 반영)'으로 남는다.

## 상태 뜻
- **장애**: 작업 실패·누락, 올리기(push)·배포 실패, 사이트 응답 오류, `_status.json` 못 읽음, 브랜치 지연(앱이 읽는 main 이 기본 가지보다 오래됨), 자료 만료, 검문 멈춤, 정책 위반(서울·경기)
- **검증 필요**: 자동 검사 실패·만료, 의미 변경 과다(파일 보류), 지역 섞임 의심, 재검증 대기, 공개 중·원문 부분 확인
- **공개 보류**: 원문 미확인으로 숨긴 자료(급식·특목·날씨)
- **복구 완료**: 직전 집계에 있던 장애·검증 필요가 사라짐(감시가 `ops/incidents_log.json` 에 자동 기록). 사람이 적는 복구 이력은 `ops/recovery_log.json`

## 한계(솔직하게)
- 공식 정보 변경의 '감지 속도' = 수집 주기(학교·학원 매일, 병원·혜택 주 1회). 별도 폴링은 API 한도 때문에 넣지 않음.
- 자동 수집 성공(auto_check)과 기관 원문 검증(official_verify)은 별개 — 전자는 기계, 후자는 사람 표본 대조. monitor.json 의 `cities.<구>.auto_pass / official_done / official_partial` 로 구분.
- change_guard 는 기록 키가 같은 것만 비교한다. 이름·주소가 동시에 바뀐 의원은 '삭제+추가'로 보인다(삭제는 비공개, 추가는 공개).
- '폐업 확인'은 원천(국립중앙의료원) 목록에서 사라진 것을 근거로 즉시 비공개하는 것이지 폐업을 증명하는 것은 아니다 — 승인 기록으로 확정한다.
